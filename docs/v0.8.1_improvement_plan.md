## 1. Primary blocker — CR heterogeneous line routing ("Cycle 2b")

**Diagnosis (from the sweep logs).** The gate cross-entropy
(`model.py:3601`, `gate_aux_loss = −Σ gate_target·log_pooled_gate`) is dominated
by the ~99% continuum majority. A **global** focal γ lifts all lines roughly
uniformly, but CR line rarities are **heterogeneous** (Al needs ~6×, Cu Kβ ~1×),
so a single γ cannot match them, and two side effects appear in the sweeps:

- Raising γ **digs the between-line continuum**: mode-C core ratio 0.728 (γ=0) →
  0.664 (γ=2) → 0.581 (γ=3). The gate steals continuum-near-line density to feed
  the lines.
- **Power-law class weights are unstable** for rare lines: `power=0.4` gave
  line_0 0.591 (collapse) while line_2 hit 1.684 (overshoot). Inverse-frequency
  weighting blows up on the rarest class.

**Fix: closed-loop PER-LINE gate weights, calibrated from measured recovery.**
The `gate_class_weights` machinery is already implemented; only the per-line
values remain, and they should be *fit*, not guessed:

```
target = 1.0
for round in 1..3:                       # short fits, synthetic then real
    measure recovery_l for each line l
    w_l ← clip( w_l * (target / recovery_l)**alpha , 1.0, cap )   # alpha≈0.5 damped, cap≈8
keep gate_focal_gamma LOW (γ=1)          # majority stability WITHOUT digging continuum
```

Damped multiplicative updates converge without the power-law overshoot; keeping
γ low avoids the continuum-digging seen at γ≥2. Persist the converged per-source
`gate_class_weights` in metadata.

**Line-collision sub-check (Cu Kβ over + Ni Kβ under are adjacent).** This pairing
is the fingerprint of the old §2a "Cu/Ni-adjacent line over-generation": the gate
may be misrouting events between adjacent Cu/Ni components. Before weighting,
diagnose per-line assignment confusion within ±a few FWHM (which component claims
events near each line). If they collide, verify the pinned line *positions* are
exact and let per-line weights separate them; if a residual leak remains, add a
small cross-line leakage penalty. Do NOT just down-weight Cu Kβ blindly — confirm
whether its overshoot is rarity mis-scaling or a collision artifact.

**Acceptance (Cycle 2b):** CR Al, Ni, 511 all in [0.8, 1.2]; Cu Kβ in [0.8, 1.2];
between-line continuum ratio ≥ 0.85; Small lines stay in [0.8, 1.3]; coupling
residuals ≤ ±0.05.

## 3. Validation hardening (beta + paper credibility)

- **Multi-seed.** All current numbers are single-seed (42). Run ≥3 seeds and
  report mean ± std on line-integral recovery, Wasserstein(energy), and the
  coupling residual matrix. A released beta and the paper's fidelity claims need
  error bars; per-line weights especially must not be a one-seed overfit.
- **Gate coupling with the coupled synthetic test.**
  `tools/synthetic_stress_test_coupled.py` injects real energy↔geometry
  correlation — unlike the single-peak noise-geometry test, it can actually
  validate the `z_cond` default. Make it the coupling CI gate.
- **One automated acceptance harness.** Fold line-integral recovery +
  between-line continuum ratio + Wasserstein(energy) + coupling residuals into a
  single pass/fail report against explicit thresholds, runnable on any checkpoint.
  This grades each ~80-min real run objectively and doubles as the paper's
  validation table.

  `prior="coupling"`, `gate_focal_gamma=1`, `gate_class_weights=<calibrated CR set>`.
  Keep v0.7.2 selectable but no longer default.

## 5. Go / no-go — making v0.8 the beta default

**Bar:** CR Al, Ni, 511 recovery ≥ 0.8 and Cu Kβ ≤ 1.2; between-line continuum
≥ 0.85; CR Compton-edge Wasserstein ≤ v0.7.2's; all coupling residuals ≤ ±0.05;
multi-seed std small.

- **Met by ~15 Aug →** v0.8 becomes the beta default; retire the v0.7.2 fallback.
- **Not met →** ship v0.7.2 as the beta (its marginal fidelity is release-grade),
  label v0.8 "experimental / opt-in," and finish v0.8.1 as a post-release point
  update. The paper still tells the v0.8 story (coupling + sub-bin lines are the
  novel contribution) with v0.8.1 numbers landing for the journal (Track B).
