# MAGI v0.8 — IAF / Normalizing-Flow integration plan

Status: design note (not yet implemented). Target: MAGI v0.8.
Author context: Francesco Monastra (INAF). Written against v0.7.2 code
(`MAGI_package/magi`), head class `CVAE_CatEnergy_ContPhi_TaskAdaptive`.

## 0. TL;DR

- Add normalizing flows to the existing cVAE **without rewriting the architecture**.
- Two independent, flag-gated upgrades:
  1. **Latent flows** — IAF on the posterior (`q(z|x)`), coupling flow on the prior (`p(z)`).
  2. **Flow output heads** — replace diagonal-Gaussian continuous heads with a conditional flow; optionally make energy continuous with a continuum-flow + explicit line components.
- Everything is a strict superset of the current model: flows off → byte-for-byte v0.7.2. Clean A/B against the existing Wasserstein diagnostics.
- **Important scoping fact:** a *latent* IAF does NOT touch the energy head, so it will not fix the emission-line under-generation. That problem lives in the categorical energy head + its loss/sampling (see §6).

## 1. Where the VAE machinery lives (v0.7.2)

Head class `CVAE_CatEnergy_ContPhi_TaskAdaptive` in `core/model.py` (defined ~line 1960). All the generative-core logic is in four places:

| Concern | Method | Approx line |
|---|---|---|
| reparameterization | `sample_z` | 2269 |
| decode from `(z, cond)` | `_decode_params` | 2301 |
| KL (analytic, closed form) | `train_step` | 2478–2484 |
| KL (analytic, closed form) | `test_step` | 2554 |
| generation `z ~ N(0,I)` | `generate` | 2592–2593 |

Two Gaussian bottlenecks are visible in the code, and they are separate:

1. **Latent**: diagonal-Gaussian posterior `q(z|x)=N(z_mean, diag(exp z_logvar))`, analytic KL vs `N(0,I)` prior.
2. **Output**: each continuous feature (`ur, uv, phi_r, phi_v`) is an independent conditional diagonal Gaussian (`*_mu`, `*_logsigma`), sampled independently in `generate()` (lines ~2597–2607).

IAF addresses (1). A flow output head addresses (2). They are orthogonal and can be shipped independently.

## 2. What each change actually buys (read before implementing)

- **Posterior IAF alone** → tighter ELBO, richer `q(z|x)`, better reconstructions/representation. **Does NOT change generation**, because `generate()` still samples `z ~ N(0,I)`. (See `generate()` line 2593.)
- **Learnable prior** → this is what actually improves *generation* fidelity (removes the prior-hole / aggregated-posterior mismatch).
- **Flow output head** → removes the diagonal-Gaussian smoothing of per-feature conditionals; captures sharp/multimodal/heavy-tailed continuous structure and cross-feature dependence.

Design implication: if the goal is faithful *generation*, posterior-IAF must be paired with a learnable prior (or a flow output head). Posterior-IAF on its own is an ELBO/representation upgrade only.

## 3. New module `core/flows.py`

Conditional autoregressive flow (IAF) for the posterior. TFP-based sketch:

```python
# core/flows.py
import tensorflow as tf
import tensorflow_probability as tfp
tfd, tfb = tfp.distributions, tfp.bijectors

class ConditionalIAF(tf.keras.layers.Layer):
    """K-step IAF over z, conditioned on `cond` (particle one-hot).
       forward: z0 -> z_K; returns z_K and sum log|det dz_K/dz0|.
       IAF = Invert(MAF): the forward (sampling) pass is one parallel pass,
       and density is only ever evaluated at self-sampled points -> cheap."""
    def __init__(self, latent_dim, cond_dim, n_steps=3, made_units=(64, 64), **kw):
        super().__init__(**kw)
        self.bijectors, self.perms = [], []
        for _ in range(n_steps):
            made = tfb.AutoregressiveNetwork(
                params=2, hidden_units=list(made_units),
                event_shape=[latent_dim],
                conditional=True, conditional_event_shape=[cond_dim],
                activation="relu")
            self.bijectors.append(tfb.Invert(tfb.MaskedAutoregressiveFlow(made)))
            self.perms.append(tfb.Permute(list(reversed(range(latent_dim)))))

    def forward_and_logdet(self, z0, cond):
        z, logdet = z0, 0.0
        for bij, perm in zip(self.bijectors, self.perms):
            ci = {"conditional_input": cond}
            logdet += bij.forward_log_det_jacobian(z, event_ndims=1, **ci)
            z = perm.forward(bij.forward(z, **ci))
        return z, logdet
```

Notes:
- TFP conditional plumbing is fiddly; a hand-rolled MADE (~60 lines) is an acceptable dependency-free alternative.
- For the **prior**, prefer affine/neural-spline **coupling** layers (RealNVP/Glow-style), NOT IAF. Coupling flows are closed-form cheap in both directions, so both training-time density and generation-time sampling stay fast — preserving MAGI's fast-sampling purpose. (IAF is cheap to sample but expensive to score external points, which the prior needs at training time.)

## 4. KL replacement (the only conceptually load-bearing edit)

Current analytic KL is valid only because q and p are both Gaussian. With a posterior flow, `z = IAF(z0)` is non-Gaussian → switch to the Monte-Carlo KL the flow makes tractable.

```python
# core/model.py — in train_step, replacing the analytic KL block (~2470-2484)
z_mean, z_logvar = self.encoder(x_in, training=True)
z0 = self.sample_z(z_mean, z_logvar)
z, logdet = self.posterior_flow.forward_and_logdet(z0, cond)   # NEW

params = self._decode_params(z, cond, training=True)           # decode flowed z

# log q(z|x) = log q0(z0) - logdet
log_q0 = -0.5 * tf.reduce_sum(z_logvar + (z0 - z_mean)**2 / tf.exp(z_logvar), axis=1)
log_qz = log_q0 - logdet

# log p(z): N(0,I) for a fixed prior, OR prior_flow.log_prob(z, cond) if learnable
log_pz = -0.5 * tf.reduce_sum(tf.square(z), axis=1)            # fixed prior
# log_pz = self.prior_flow.log_prob(z, cond)                   # learnable prior

kl_per = log_qz - log_pz
kl = tf.reduce_mean(kl_per)
```

Apply the identical change in `test_step`. Everything downstream (`_reconstruction_terms`, TaskAdaptive weighting, sigma reg) is unchanged.

## 6. Emission-line under-generation — diagnosis & fixes (SEPARATE from IAF)

Symptom (Francesco): spectral lines are generated *lower* than in the training set; a line bin is "treated like any other bin."

**IAF will not fix this.** Energy is a categorical softmax head over `n_energy_bins`, decoupled from the latent. The line problem is in the energy head + its loss + its sampling, not in `z`. Concrete suspects in the current code:

1. **Label smoothing** (`losses.smoothed_categorical_ce`, `local_neighbors=True`) actively moves probability mass off the true bin onto neighbors → directly lowers sharp line peaks. Do not smooth line bins (or disable smoothing for them).
2. **`energy_sampling_temperature`** (`_sample_energy_from_logits`, line ~2586): T>1 flattens the categorical and lowers peaks. Use T≤1 for lines.
3. **In-bin uniform sampling** (`sampling.energy_from_idx`, `mode="uniform"`) spreads a near-delta line uniformly across the full bin width → broadens the line and drops its peak height. For line bins, sample at the physical line energy (delta / narrow Gaussian at detector resolution) instead of uniform.
4. **TaskAdaptive weight decay** on the `energy` task may under-train the energy head — check the decay schedule / final `w_energy`.
5. **Binning**: consider non-uniform bins (fine at lines, coarse in continuum), or give each known line its own bin.

## 7. Making energy continuous — recommended structure

A pure "energy as continuous variable modeled by a flow" is tempting but risky: a spectral line is a near-delta, and sharp spikes are the *hardest* case for continuous density models (MLE with smooth transforms tends to under-peak them → the SAME "generated lower" symptom can reappear).

Recommended: model energy as a **mixture (hurdle) of continuum + explicit line components**, which maps naturally onto the existing multi-head decoder and does NOT require abandoning the cVAE:

```
p(E | z, cond) = pi_cont * f_flow(E | z, cond)          # smooth continuum via a conditional flow
               + sum_l pi_l * N(E; mu_l, sigma_l)        # one narrow component per known line
```

- Line positions `mu_l` can be fixed from physics (known decay energies) or learned; `sigma_l` ~ detector resolution.
- The mixture weights `pi` are a small categorical head — but over `{continuum, line_1, ..., line_L}`, not over hundreds of continuum bins. Lines get their own protected weight instead of competing in a wide softmax eroded by label smoothing.
- This fixes the under-generation (lines are explicit components) AND makes the continuum continuous.

## 8. Adding NF to the cVAE WITHOUT starting over

Two additive ways, both keep the encoder, TaskAdaptive scaffolding, and training loop:

- **Latent flow** (§3–§5): IAF posterior + coupling prior.
- **Flow / mixture output heads** (§6–§7): replace diagonal-Gaussian continuous heads with a conditional flow `p(y_cont | z, cond, E)`, and/or the energy mixture above.

This "cVAE with flow-based likelihood" hybrid is the recommended sweet spot: keep the cVAE's conditional latent structure and interpretability, upgrade only the output density. It is strictly less disruptive than replacing the whole model with a standalone conditional NF.

## 9. Flags, checkpointing, A/B

- Constructor kwargs: `posterior_flow=None`, `prior_flow=None`, (`energy_mode="categorical"|"continuous_mixture"`, `cont_head="gaussian"|"flow"`). All `None`/defaults → exact v0.7.2 behavior.
- `training/checkpointing.py`: persist a `"flow"` block in `*_metadata.json` (flow type, n_steps, MADE units, whether it conditions on `cond`, energy_mode). Given the known string-key train↔generate drift risk, add an assertion at generation-load time that the saved flow config matches the constructed model.
- A/B: run current vs. IAF vs. IAF+prior vs. flow-head through the existing `report_*` / Wasserstein validation on identical preprocessed datasets.

## 10. Effort estimate

- Phase 1 (posterior IAF + KL swap + checkpoint fields): ~1 day (mostly TFP conditional-flow plumbing).
- Phase 2 (learnable coupling prior + generation swap): ~1–2 days.
- Energy mixture / flow output head: separate workstream, size depends on how many lines are modeled explicitly.
